# ObserV6 平台功能与使用说明

ObserV6 是 IPv6 网络探测与观测平台：主动探测（XMap 活跃性扫描、ZGrab2 服务探测）、数据沉淀（国家 / AS / 前缀 / 地址库）、可视化分析和 AI Agent。

## 功能模块
- **XMap 扫描**（`/tools/xmap`）：对目标地址或网段做活跃性扫描。创建任务后进入队列，由调度器按并发上限执行；可取消、查看日志、下载结果。
- **ZGrab2 探测**（`/tools/zgrab2`）：对地址列表或已上传的输入文件做应用层探测（http、ssh、smtp、tls 等模块）。**扫描预设**是“模块 + 端口”的套件（邮件、工控、Web、数据库、远程管理与文件、消息队列与物联网等），套用后生成多模块配置文件；也可以保存自己的预设。
- **别名前缀检测（APD）**（`/tools/apd`）：对候选前缀的 16 个子前缀各探测一个随机地址：16 个都应答判为别名前缀，都不应答为干净，其余为“不确定”（不入库，建议降速复测）。已知别名前缀可用于过滤地址列表。
- **目标生成（TGA）**（`/tools/tga`）：以已知活跃地址为种子生成候选目标，不发包。算法：`density-expand`（密度扩展，6Gen 思路）、`subnet-walk`（子网枚举）、`nibble-dist`（位置分布采样，Entropy/IP 思路）。种子来自上传文件，或库里某前缀/AS 的活跃地址。生成结果保存为输入文件，可交给 XMap/ZGrab2。
- **地址分类与富化**（`/tools/enrich`）：按接口标识（IID）把地址分为低位编号、EUI-64、嵌入 IPv4、随机等类型（基于规则的启发式，没有做准确率评测）；管理员可对库内地址批量分类并补全所属前缀（后台任务）。
- **导入批次与变化**（`/tools/history`）：每次导入记为一个批次；同一前缀的两个批次可以对比新增、消失、保留的地址。
- **工作流**（`/tools/workflows`）：把 XMap →（别名过滤）→ ZGrab2 等步骤编排成流程，可暂停、恢复、取消。
- **高级查询**（`/detection/query`）：按国家（两位代码，如 CN）、AS、前缀、协议、漏洞、首次/最近发现日期等条件组合查询地址库。时间取自该地址各协议记录的最早/最晚时间，没有协议记录的地址没有时间；库里不记录在线率。
- **趋势**（检测页顶部“趋势”按钮，以及国家 / ASN 详情）：每天一次的统计快照，显示活跃地址数和前缀数的变化。刚启用时只有一个数据点，要隔几天才有曲线。
- **任务报告**：xmap / zgrab2 任务结束后，在任务详情点“导出报告”，得到包含任务信息、结果概览、状态分布和样例的 HTML 报告（浏览器可打印为 PDF）。
- **开放只读 API**（`/api/open/v1`）：管理员发放 API 密钥后，合作方可读取统计与趋势；完整地址需要单独的 `addresses` 权限。用法见开放 API 文档。
- **Agent**（`/tools/agent`）：用自然语言驱动工具。

## Agent 能做什么
Agent 的工具：`xmap`、`zgrab2`、`apd_detect`、`generate_targets`、`enrich`（仅管理员）、`query_database`（只读）、`task_status`（只读）、`knowledge`（知识问答，先检索知识库）、`workflow`（生成工作流）、`terminal`（仅管理员）。
- **会产生实际影响的工具一律需要用户确认**：扫描、探测、创建任务、修改数据库、执行终端命令。Agent 先给出参数，用户在界面上点“确认”才执行；模型自己不能确认。
- 一次对话里最多处理 3 个工具调用（`AGENT_MAX_TOOL_CALLS`），多出的会告知用户。
- 工具返回的外部内容（任务描述、数据库记录等）被当作资料而不是指令，里面写的“忽略规则”之类不会被执行。
- 所有工具调用写入审计日志；成功执行的记入用户自己的工具历史。

## 任务状态
`pending`（排队中）→ `running`（运行中）→ `completed`（已完成）/ `failed`（失败）/ `canceled`（已取消）。终态不会被覆盖。服务重启后，仍在运行状态但进程已不存在的任务会被标记为失败。

## 合规与扫描策略
- 主动扫描只能针对你拥有或获得书面授权的网络。开发与测试阶段不对外部网络扫描。
- **默认拒绝**：目标必须完整落在管理员配置的白名单内（`SCAN_ALLOWED_TARGETS` 或管理员页面）。部署后没有配置白名单时，所有扫描都会返回 403。
- 回环、组播、链路本地（含 169.254.0.0/16 云元数据）等地址永远拒绝；黑名单与目标有交集即拒绝；域名不被接受。
- XMap 与 APD 的速率有上限（`SCAN_MAX_RATE`），每个用户每天的任务数有上限（`SCAN_DAILY_LIMIT`，三类扫描合计）。
- 策略只在创建任务时检查，排队期间名单变化不会重新检查。

## 常见问题
- **扫描返回 403 怎么办？** 目标不在白名单内，或超过速率/配额。请管理员在白名单里加入你有授权的网段。
- **ZGrab2 的输入文件怎么来？** 在文件管理里上传（每行一个地址），或在目标生成 / 别名过滤 / Agent 里生成；任务只能引用自己的文件。
- **为什么“活跃地址数”要先做别名过滤？** 别名前缀对前缀内任意地址都应答，不过滤会把活跃数夸大几个数量级。
- **为什么 APD 结果是“不确定”？** 16 个探测只有部分应答：可能是丢包、限速或部分子前缀别名。降低速率后复测。
