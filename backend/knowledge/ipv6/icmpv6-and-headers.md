# IPv6 报头、扩展头与 ICMPv6

> 本文是摘要，不是 RFC 原文，细节以 RFC 8200（IPv6 规范）、RFC 4443（ICMPv6）、RFC 4890、RFC 5095、RFC 7112、RFC 8201、RFC 9099 为准。

## 基本报头（RFC 8200）
IPv6 报头固定 40 字节，字段有：版本、流量类别、流标签（20 位）、载荷长度、下一报头、跳数限制（相当于 IPv4 的 TTL）、源地址、目的地址。没有首部校验和，没有分片字段（分片信息放在扩展头里）。

## 扩展头
可选功能放在扩展头中，按“下一报头”字段串成链：逐跳选项、路由头、分片头、目的选项、认证头 AH、封装安全载荷 ESP 等。
- **分片只由源节点做**，中间路由器不分片；链路最小 MTU 是 1280 字节。
- 路径 MTU 发现（PMTUD，RFC 8201）依赖 ICMPv6 “数据包过大”消息。过滤了这类消息会造成连接黑洞。
- **路由头类型 0（RH0）** 因可被用于放大攻击已被弃用（RFC 5095）。
- 分片头与安全：RFC 7112 要求第一个分片必须包含完整的报头链（上层头），否则防火墙无法检查；重叠分片、微小分片曾被用来绕过检测。

## ICMPv6（RFC 4443）
ICMPv6 在 IPv6 中是必需的，不能像 IPv4 那样整体过滤。

| 类型 | 名称 |
|---|---|
| 1 | 目的不可达 |
| 2 | 数据包过大（PMTUD 必需） |
| 3 | 超时（跳数耗尽，traceroute 依赖） |
| 4 | 参数问题 |
| 128 / 129 | 回显请求 / 回显应答（ping6） |
| 133–137 | 邻居发现相关，见 `ndp-slaac.md` |

RFC 4890 给出了防火墙对 ICMPv6 的过滤建议：必须放行数据包过大、超时、参数问题、目的不可达以及 NDP 报文（在本链路上）；回显请求可以按策略限制。
运营安全建议汇总在 RFC 9099（IPv6 运营安全考虑）。
