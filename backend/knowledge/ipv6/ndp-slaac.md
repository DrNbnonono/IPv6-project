# 邻居发现（NDP）与无状态地址自动配置（SLAAC）

> 本文是摘要，不是 RFC 原文，细节以 RFC 4861（邻居发现）、RFC 4862（SLAAC）、RFC 8981（临时地址）、RFC 7217、RFC 8064、RFC 7136 为准。

## 邻居发现协议（NDP，Neighbor Discovery Protocol，RFC 4861）
NDP 运行在 ICMPv6 之上，取代 IPv4 里的 ARP、ICMP 路由器发现和重定向。五种消息：

| ICMPv6 类型 | 消息 | 作用 |
|---|---|---|
| 133 | 路由器请求 RS | 主机请求路由器立刻发送 RA |
| 134 | 路由器通告 RA | 路由器通告前缀、默认路由、MTU、M/O 标志 |
| 135 | 邻居请求 NS | 解析邻居的链路层地址；重复地址检测；邻居不可达检测 |
| 136 | 邻居通告 NA | 回应 NS，或主动通告链路层地址变化 |
| 137 | 重定向 | 路由器告诉主机有更优的下一跳 |

- 地址解析用**被请求节点组播地址**：`ff02::1:ff` 加目标地址的低 24 位，只有可能拥有该地址的节点会收到。
- **重复地址检测（DAD）**：配置地址前先用 NS 询问有没有人在用，源地址为未指定地址 `::`。
- **邻居不可达检测（NUD）**：持续确认邻居仍然可达。
- NDP 消息的跳数限制必须是 255，以保证消息来自本链路，不能被路由转发过来。
- 安全：NDP 本身没有认证，链路上的攻击者可以伪造 RA/NA（RA 欺骗、邻居缓存投毒）。缓解办法有 RA Guard（RFC 6105）、DHCPv6 Shield、SEND（RFC 3971，实际部署很少）、交换机上的 ND 检查与限速。

## 无状态地址自动配置（SLAAC，RFC 4862）
1. 主机用链路本地地址（`fe80::/10` + IID）通过 DAD 后，发 RS。
2. 路由器 RA 里的前缀信息选项（PIO）带 **A 标志（Autonomous）**：主机用该前缀 + 自己的 IID 生成全球地址；**L 标志（On-link）**表示该前缀在本链路上直接可达。
3. RA 里的 **M 标志**表示地址要通过 DHCPv6 获得，**O 标志**表示其他配置（如 DNS）通过 DHCPv6 获得。
4. 地址有首选寿命和有效寿命，到期后弃用/删除。

## 接口标识（IID）的隐私问题
- 修改的 EUI-64 把 MAC 地址放进 IID，跨网络可跟踪。
- **临时地址**（RFC 4941，被 RFC 8981 取代）：随机 IID，定期更换，用于对外发起连接。
- **稳定隐私地址**（RFC 7217）：IID = 哈希(前缀, 接口, 网络标识, DAD 计数, 密钥)，同一网络稳定、跨网络不同。RFC 8064 建议默认用它而不是 EUI-64。
- RFC 7136：IID 的各位没有特定语义，不应该从 IID 推断设备类型。
- 对测量的影响：随机 IID 和稳定隐私 IID 的地址空间无法靠枚举覆盖，只能靠已知地址（DNS、NTP、日志、被动数据）发现。
