# IPv6 地址架构（RFC 4291）

> 本文是摘要，不是 RFC 原文，细节以 RFC 4291、RFC 4193、RFC 3849 为准。

## 基本格式
IPv6 地址长 128 位，写成 8 组 16 位十六进制数，组间用冒号分隔。每组前导 0 可以省略，一段连续的全 0 组可以用 `::` 替换一次（只能一次）。前缀写法是 `地址/前缀长度`，如 `2001:db8::/32`。
地址分为前缀（网络部分）和接口标识（IID，Interface Identifier）。对大多数单播地址，接口标识为 64 位，所以子网通常是 /64。

## 地址类型
- **单播**：标识一个接口。包括全球单播、链路本地、唯一本地地址（ULA）。
- **组播**：标识一组接口，前缀 `ff00::/8`。IPv6 没有广播，原来广播的功能由组播承担。
- **任播**：同一个地址分配给多个节点，数据包送到“最近”的一个。

## 常见前缀
| 前缀 | 含义 |
|---|---|
| `::/128` | 未指定地址（只能作源地址，如重复地址检测时） |
| `::1/128` | 环回地址 |
| `fe80::/10` | 链路本地地址，只在本链路有效，每个接口自动配置 |
| `fc00::/7` | 唯一本地地址 ULA（RFC 4193），相当于 IPv4 私网地址，实际使用 `fd00::/8` |
| `2000::/3` | 全球单播地址（目前 IANA 从这里分配） |
| `ff00::/8` | 组播 |
| `::ffff:0:0/96` | IPv4 映射地址（`::ffff:192.0.2.1`），用于双栈套接字表示 IPv4 |
| `2001:db8::/32` | 文档示例专用（RFC 3849），不会出现在公网 |
| `64:ff9b::/96` | NAT64 的知名前缀（RFC 6052） |

## 接口标识的生成方式
- **修改的 EUI-64**：由 48 位 MAC 地址中间插入 `ff:fe`，并翻转第 7 位（U/L 位）得到。地址里含有硬件厂商信息，且同一设备在不同网络里 IID 不变，可被跟踪。
- **临时地址（隐私扩展）**：随机生成并定期更换，见 `ndp-slaac.md`。
- **稳定且不透明的 IID**（RFC 7217）：由前缀、接口、密钥等哈希得到，同一网络里稳定、换网络就变。
- **手工/DHCPv6 分配**：常见低位编号（`::1`、`::2`、`::a`），在扫描中容易被猜到。

## 子网与 /64
RFC 4291 规定非 000 开头的单播地址 IID 为 64 位，SLAAC 依赖这一点，因此终端子网几乎总是 /64。一个站点通常从 ISP 获得 /48 或 /56，可以划出 65536 或 256 个 /64 子网。
