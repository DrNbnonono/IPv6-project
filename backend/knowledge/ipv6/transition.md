# IPv4 到 IPv6 的过渡技术

> 本文是摘要，不是 RFC 原文，细节以 RFC 4213、6052、6146、6147、6877、3056、7526、4380、8215 为准。

## 双栈（Dual Stack，RFC 4213）
主机和网络同时运行 IPv4 和 IPv6，应用按 Happy Eyeballs（RFC 8305）同时尝试两种协议、选用更快的。双栈最简单，但需要继续维护 IPv4 地址和两套安全策略。

## 隧道
把 IPv6 包封装进 IPv4 包穿过纯 IPv4 网络。
- **配置隧道 / 6in4**：手工配置两端，协议号 41。隧道代理（tunnel broker）常用。
- **6to4**（RFC 3056，前缀 `2002::/16`）：6to4 任播中继已被弃用（RFC 7526），不建议再使用。
- **Teredo**（RFC 4380，前缀 `2001::/32`）：穿透 NAT 的 UDP 隧道，现在基本不再使用。
- **ISATAP**（RFC 5214）：站内自动隧道，已过时。
- 安全上，隧道会绕过边界防火墙对 IPv6 流量的检查，要在入口处管控协议 41 和 UDP 隧道。

## 翻译（IPv6-only 网络访问 IPv4 资源）
- **NAT64**（RFC 6146）：有状态翻译器，把 IPv6 客户端的流量翻译成 IPv4，知名前缀是 `64:ff9b::/96`（RFC 6052），IPv4 地址嵌入 IPv6 地址的低 32 位。RFC 8215 另给出本地使用的 `64:ff9b:1::/48`。
- **DNS64**（RFC 6147）：当域名只有 A 记录时，合成一个 AAAA 记录（NAT64 前缀 + IPv4 地址），让 IPv6-only 客户端能通过 NAT64 访问。
- **464XLAT**（RFC 6877）：在 IPv6-only 网络里给只会 IPv4 的应用提供支持：客户端上的 CLAT 先把 IPv4 翻成 IPv6，运营商的 PLAT（NAT64）再翻回 IPv4。手机运营商广泛使用。
- 对测量的影响：从 IPv6-only 网络里扫描嵌入 NAT64 前缀的地址，实际探测到的是 IPv4 服务；识别 `64:ff9b::/96` 这类地址要避免把它们当作原生 IPv6 主机统计。
