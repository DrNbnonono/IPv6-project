# 演示准备、快照回滚与演示脚本（P6-2）

> 这份脚本里**需要真实扫描工具或模型密钥的步骤**（第 2、7 步）没有在开发环境里端到端跑过——开发阶段不对外扫描，也没有配模型密钥。请在演示环境按「演示前一周的彩排」完整走一遍，再据此调整时间。

## 1. 演示前：快照与回滚

```bash
cd backend
# 环境准备好、数据导入完成后，拍一个“干净状态”的快照（含扫描结果等数据目录）
npm run demo:snapshot -- create before-demo --with-files
npm run demo:snapshot -- list

# 演示中创建了任务、写了数据，想回到演示前（必须带 --confirm-db，值等于当前 DB_NAME）
npm run demo:snapshot -- restore before-demo --confirm-db ipv6_project
```

要点：
- 还原前会自动再留一个 `auto-before-restore-*` 安全快照，输出里会给出撤销命令；
- 只还原快照里有的表和文件；快照之后新增的表、结果文件不会被删除；
- 若当前账号没有权限读存储过程（过程由 root 创建、你用普通账号），快照会不含存储过程，还原时现有过程不受影响；
- 快照目录 `demo_snapshots/` 已 gitignore，里面有用户表（密码哈希）和 API 密钥哈希，**不要提交或外传**；
- 容器部署时在后端容器里执行（镜像里有 mysql 客户端），快照目录要挂到卷上，否则容器重建会丢；
- 已在 MariaDB 10.11 上做过往返验证（改行、删行、删文件后还原一致，触发器还原正常）；MySQL 8 由 CI 的“演示快照往返”步骤验证。

## 3. 演示流程（建议 8–10 分钟）

| # | 看点 | 操作 | 预期 | 备注 |
|---|---|---|---|---|
| 1 | 全局态势 | 打开 `/detection-platform`：地球仪、左右排名榜；点“成果”进入 `/detection/highlights` | 规模、协议/漏洞分布、近 N 天趋势 | 成果页是公开的，适合评委自己再点 |
| 2 | 扫描 | `/tools/xmap`：配置参数 → 提交任务（目标必须在白名单内） | 任务进入 running，日志实时滚动 | **需要 xmap**；无白名单会 403，这本身也是合规亮点，可顺带展示管理员页的白名单/配额/审计 |
| 3 | 别名前缀过滤 | `/tools/apd`：新建检测，选刚才的结果 | 列出疑似别名前缀，过滤后的地址更干净 | 需要 xmap 做探测；别名检测的算法与阈值见页面说明 |
| 4 | 入库 | `/tools/database`：把过滤后的结果导入 | 批次号生成；`/tools/history` 可看到新批次 | 导入任务耗时与数据量有关，提前量好 |
| 5 | 趋势与差异 | 回到检测平台“趋势”；`/tools/history` 选两个批次做差异 | 新增/消失/持续地址三类数量 | 趋势曲线靠每日快照，没有几天数据时**不要**用 `npm run stats:snapshot -- <过去的日期>` 补点——补写的历史快照读的是当前数据，会得到和今天相同的数字，等于伪造趋势；等真实累积的点 |
| 6 | 报告 | 打开该扫描任务详情 → “导出报告” | 下载一份自带样式的 HTML 报告 | 报告里扫描结果内容全部转义，可展示这一点 |
| 7 | Agent 对话 | `/tools/agent`：问 3 个问题——① 平台现在有多少活跃 IPv6 地址？② 帮我查某个国家的协议分布 ③ 刚才那个扫描任务状态如何？ | 触发数据库查询/任务查询工具，答案带出处 | **需要模型密钥**；工具调用有审计，可在管理员页展示 |
| 8 | 开放 API（可选） | 终端 `curl -H "X-API-Key: ov6_…" …/api/open/v1/stats/global` | JSON 聚合数据 | 对公网开放前请再复核数据范围（`addresses` 权限默认不授予） |

## 4. 现场故障预案

| 现象 | 处理 |
|---|---|
| 扫描任务起不来 / 403 | 先看管理员页“审计日志”的拒绝原因（多半是目标不在白名单）；改用已有的历史任务讲解 |
| 工具（xmap/zgrab2）不在机器上 | 直接用历史任务与已导入的结果演示第 3–6 步 |
| 模型接口超时 | 换预先准备好的备用问题；或展示审计页里已有的 Agent 调用记录 |
| 数据被演示弄乱 | `npm run demo:snapshot -- restore before-demo --confirm-db <库名>` |
| 网络彻底不可用 | 放断网备用录屏（见彩排清单） |
| 后端挂了 | 容器部署：`docker compose restart backend`；先看 `/api/health` |
