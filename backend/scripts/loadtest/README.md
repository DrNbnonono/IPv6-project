# 压测（P6-1）

用 `scripts/loadTest.js` 做“并发 → 延迟”阶梯测试，用 `seed-synthetic.sql` 在**压测专用库**里灌合成数据。两者都不依赖额外 npm 包。

## 怎么跑

```bash
# 1. 准备压测库（不要用生产库）：建表 → 迁移 → 灌合成数据（需要 MariaDB 的 seq 引擎）
mysql 压测库 < structure.sql                      # 沙箱用的是 MariaDB 兼容版本
node scripts/migrate.js                          # 迁移 14 的 ngram 在 MariaDB 不支持，压测不需要知识库，可单独执行 15、16
mysql 压测库 < scripts/loadtest/seed-synthetic.sql
for d in $(seq 29 -1 0); do node scripts/statsSnapshot.js $(date -d "-$d day" +%F); done   # 30 天快照，趋势接口才有曲线

# 2. 启动后端（调高全局限流，否则测到的是限流器）
API_RATE_MAX=100000000 node app.js

# 3. 压测
node scripts/loadTest.js --scenario detection --levels 1,5,10,25,50,100,200 --duration 8
node scripts/loadTest.js --scenario open --api-key ov6_xxx --out load-report.json
```

脚本拒绝非本机目标，除非加 `--i-own-this-target`。429 占比超过 1% 时会提示“测到的是限流器”。

## 合成数据

60 国家 / 800 ASN / 8000 个 /48 前缀 / 30 万地址 / 约 39 万条协议记录 / 3 万条漏洞记录，地址全部在文档保留段 `2001:db8::/32` 内。灌数据前会删除统计触发器（逐行触发统计太慢），统计表在脚本末尾一次性聚合——**只能用在压测库**。

## 一次实测（2026-10-24）

环境：2 vCPU 沙箱，MariaDB 10.11 与 Node 22 同机，**压测脚本也在同一台机器上抢 CPU**，单个 Node 进程。数字只说明“这套代码在这个规模下的相对行为”，不能当作生产容量。两次重复结果相差在 10% 以内。

检测平台公共接口（10 个接口轮流，含 map-data 88KB、排名榜、趋势、搜索）：

| 并发 | rps | p50 ms | p95 ms | p99 ms |
|---:|---:|---:|---:|---:|
| 1 | 381–453 | 2.0 | 5.2 | 7.3 |
| 5 | 910 | 4.8 | 11.4 | 15.6 |
| 10 | 1100 | 8.1 | 19.2 | 25.9 |
| 50 | 1110–1203 | 41–44 | 72–78 | 84–95 |
| 100 | 1096–1110 | 90 | 153 | 177–187 |
| 200 | 1052 | 189 | 327 | 359 |

开放 API（6 个接口，key 限流调到 100000/分钟）：

| 并发 | rps | p50 ms | p95 ms | p99 ms |
|---:|---:|---:|---:|---:|
| 1 | 525–549 | 1.6 | 3.8 | 4.6 |
| 10 | 1402–1434 | 6.2 | 13.3 | 17.9 |
| 50 | 1238–1466 | 32–38 | 53–65 | 64–80 |
| 100 | 1381–1430 | 65–69 | 102–109 | 120–125 |
| 200 | 1292 | 143 | 232 | 260 |

所有阶梯 0 个 5xx、0 个连接失败。

**怎么读**：吞吐在并发 10 左右到顶（检测平台约 1100 rps，开放 API 约 1400 rps，受单进程 CPU 限制），之后并发再高只是排队，延迟随并发线性增长（Little 定律：并发 ≈ rps × 延迟），没有出现吞吐崩塌或错误。

**限流行为**：默认配置的 key（60 次/分钟）在并发 20 下，5 秒内 59 次成功、其余约 1.4 万次全部返回 429，拒绝请求的 p50 只有 6.5ms，限流器本身不是瓶颈。

## 局限

- 数据只有 30 万地址；真实库在亿级时，没有走索引的查询会明显变慢，需要用真实副本库重测（`address_id` 游标分页和各统计表是为此设计的，但没有实测过）。
- 闭环压测不等于真实到达过程；没有测登录、扫描任务、Agent 对话（它们受 LLM 与外部工具限制，不是这类吞吐问题）。
- 没有测 MySQL 8 上的表现（沙箱只有 MariaDB）。
- 没有开启压缩：`map-data` 约 88KB，生产建议由反向代理做 gzip。
